# اجرای پروژه روی لپ‌تاپ دوست من و نمایش سر کلاس

برای ارائه **آموزش مجدد، Colab، GPU، اتصال Drive و دانلود LA.zip لازم نیست**. مدل آماده در `pretrained/full_seed0.pt` قرار دارد. Python و وابستگی‌ها را قبل از کلاس روی همان لپ‌تاپ نصب می‌کنم. بعد از نصب و دریافت پروژه، اجرای دمو به اینترنت نیاز ندارد.

سه نوع نمایش را از هم جدا می‌کنم:

1. **مرور نتایج قبلی:** CSV، ROC، EER و تصاویر موجود را باز می‌کنم؛ محاسبهٔ مدل جدیدی انجام نمی‌شود.
2. **اجرای زندهٔ مدل:** به یک فایل صوتی جدید امتیاز می‌دهم و Grad-CAM آن را می‌سازم.
3. **آموزش مجدد:** برای این ارائه انجامش نمی‌دهم. `train.py`، `pilot.py`، `run_all.sh` یا Run All نوت‌بوک آموزش را به‌عنوان دموی ساده اجرا نمی‌کنم.

## ۱. قبل از کلاس چه چیزهایی آماده کنم؟

- یک لپ‌تاپ با Python 3.12 و Git؛ اگر Git نباشد، ZIP مخزن را از GitHub می‌گیرم و extract می‌کنم.
- پروژه با پوشهٔ `pretrained`؛ فقط فایل‌های `.py` را کپی نمی‌کنم.
- یک یا دو فایل **گفتار WAV یا FLAC** که برچسب واقعی/جعلی آن‌ها را از منبع می‌دانم و اجازهٔ استفاده از آن‌ها را دارم. فایل واقعیِ ضبط‌شده با صدای خودم هم برای نمایش ورودی مناسب است. نمونهٔ جعلی باید از منبع مشخص باشد؛ یک صدای معمولی را صرفاً برای نمایش، جعلی معرفی نمی‌کنم.
- فایل‌ها را مثلاً با نام‌های `samples/real.wav` و `samples/fake.wav` قرار می‌دهم. این دو فایل نمونه، داخل مخزن نیستند و خودم تهیه می‌کنم.
- قبل از کلاس نصب و هر دو فرمان دمو را روی همان لپ‌تاپ امتحان می‌کنم. محیط `.venv` ساخته‌شده روی مک را برای ویندوز کپی نمی‌کنم؛ آنجا محیط جدید می‌سازم.

## ۲. نصب روی ویندوز — PowerShell

فرمان‌ها را از پوشه‌ای که می‌خواهم پروژه آنجا باشد اجرا می‌کنم. اگر پروژه قبلاً clone شده است، داخل همان پوشه `git pull` می‌زنم.

```powershell
git clone https://github.com/AminSalem20181/audio-deepfake-detector.git
cd audio-deepfake-detector
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install torch==2.5.1 torchaudio==2.5.1 --index-url https://download.pytorch.org/whl/cpu
.\.venv\Scripts\python.exe -m pip install -r requirements-classroom.txt
```

من مستقیم Python داخل محیط را صدا می‌زنم؛ لازم نیست برای فعال‌کردن `Activate.ps1` تنظیمات PowerShell را عوض کنم. اگر `py -3.12` پیدا نشد، Python 3.12 هنوز با این launcher نصب نیست؛ نصب Python را پیش از کلاس انجام می‌دهم.

جفت نسخهٔ PyTorch/TorchAudio بالا در محیط محلی پروژه تست شده است. فرمان CPU ویندوز/لینوکس بر پایهٔ [راهنمای رسمی نسخه‌های PyTorch](https://pytorch.org/get-started/previous-versions/) است؛ برای پروژه به torchvision نیاز ندارم.

## ۳. نصب روی مک یا لینوکس

در مک، با Python 3.12 نصب‌شده:

```bash
git clone https://github.com/AminSalem20181/audio-deepfake-detector.git
cd audio-deepfake-detector
python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements-classroom.txt
```

در لینوکس برای نصب CPU می‌توانم پیش از فرمان آخر، این فرمان را اجرا کنم:

```bash
.venv/bin/python -m pip install torch==2.5.1 torchaudio==2.5.1 --index-url https://download.pytorch.org/whl/cpu
```

اولین نصب به اینترنت نیاز دارد و ممکن است زمان‌بر باشد؛ آن را به شروع ارائه موکول نمی‌کنم. نسخهٔ محلی ۳٫۱۲ تست شده است؛ محیط GPU قبلی Colab نسخهٔ جداگانهٔ خودش را داشت و برای این دمو لازم نیست.

## ۴. اجرای زنده روی یک فایل واقعی و یک فایل جعلی

ویندوز:

```powershell
.\.venv\Scripts\python.exe scripts/demo_audio.py --audio "samples/real.wav" --label bonafide --output results/demo/real
Start-Process .\results\demo\real\report.html

.\.venv\Scripts\python.exe scripts/demo_audio.py --audio "samples/fake.wav" --label spoof --output results/demo/fake
Start-Process .\results\demo\fake\report.html
```

مک/لینوکس:

```bash
.venv/bin/python scripts/demo_audio.py --audio samples/real.wav --label bonafide --output results/demo/real
.venv/bin/python scripts/demo_audio.py --audio samples/fake.wav --label spoof --output results/demo/fake
```

بعد فایل‌های `results/demo/real/report.html` و `results/demo/fake/report.html` را با دوبار کلیک در مرورگر باز می‌کنم. در مک می‌توانم `open results/demo/real/report.html` بزنم؛ در لینوکسِ دارای محیط دسکتاپ `xdg-open results/demo/real/report.html` معمولاً همین کار را می‌کند.

این فرمان‌ها خودکار مدل نمونهٔ **full با seed صفر** را بارگذاری می‌کنند. seed صفر نمونهٔ نمایشی ثابتی است؛ بهترین مدل براساس نتیجهٔ test انتخاب نشده است. برای نمونهٔ مدل بدون SEGM:

```bash
python scripts/demo_audio.py --audio samples/real.wav --checkpoint pretrained/no_segm_seed0.pt --label bonafide --output results/demo/no_segm
```

در فرمان آخر `python` را با مسیر Python محیط خودم جایگزین می‌کنم. برچسب `--label` فقط برای نمایش درست/غلط بودن این مثال است؛ وارد مدل یا انتخاب آستانه نمی‌شود. اگر برچسب را نمی‌دانم، گزینهٔ `--label` را حذف می‌کنم.

## ۵. هنگام دیدن گزارش چه توضیح بدهم؟

از زبان من:

> «این فایل را به همان پیش‌پردازش مدل می‌دهم: تک‌کاناله، ۱۶ کیلوهرتز و چهار ثانیه. اگر فایل بلند باشد crop مرکزی استفاده می‌شود و اگر کوتاه باشد تکرار می‌شود. صوتی که اینجا می‌شنویم دقیقاً چهار ثانیهٔ پردازش‌شده است؛ فایل اولیه تغییر نکرده است.
>
> این عدد، امتیاز spoof است. اگر حداقل ۰٫۵ باشد مدل برچسب spoof می‌دهد و در غیر این صورت bonafide. این عدد دقت مدل یا احتمال تضمین‌شدهٔ درست‌بودن پاسخ نیست. اینجا سمت چپ log-Mel ورودی و سمت راست Grad-CAM برای امتیاز spoof را می‌بینیم.
>
> اگر نتیجه با برچسب مرجع متفاوت باشد، مدل این نمونه را اشتباه تشخیص داده است. دو مثال درست هم دقت کلی را اثبات نمی‌کنند؛ برای دقت کلی، جدول ارزیابی سه seed و سه دیتاست را نشان می‌دهم.»

چهار فایل خروجی ساخته می‌شود:

| فایل | کاربرد |
| --- | --- |
| `report.html` | گزارش یک‌فایلی قابل بازشدن آفلاین، همراه تصویر و صوتِ تعبیه‌شده |
| `prediction.json` | امتیاز، آستانه، مدل، seed، hash و نتیجهٔ نمونه |
| `gradcam.png` | تصویر log-Mel و Grad-CAM |
| `processed.wav` | ورودی صوتی چهارثانیه‌ای پردازش‌شده |

فایل‌های ورودی محلی در `samples/` و خروجی‌های دمو در `results/demo/` از Git کنار گذاشته شده‌اند تا صوت‌های انتخابی من خودکار منتشر نشوند.

## ۶. ترتیب پیشنهادی ارائهٔ پنج‌دقیقه‌ای

1. **نیم دقیقه:** مسئله و مدل ۳۰٬۴۳۴پارامتری را توضیح می‌دهم.
2. **یک دقیقه:** یکی از فرمان‌های بالا را زنده اجرا می‌کنم؛ فایل صوتی، امتیاز و Grad-CAM را نشان می‌دهم.
3. **یک دقیقه:** نمونهٔ دوم را اجرا می‌کنم و درست یا غلط بودنش را صادقانه می‌گویم.
4. **یک دقیقه:** `results/pilot-summary/README_FA.md` و `figures/eer_comparison.png` را نشان می‌دهم. توضیح می‌دهم Accuracy با EER فرق دارد و میانگین سه seed گزارش شده است.
5. **یک دقیقه:** ROC و ماتریس آشفتگی را باز می‌کنم و افت دامنهٔ بیرونی را توضیح می‌دهم.
6. **نیم دقیقه:** محدودیت pilot و مسیر مطالعهٔ بعدی را جمع‌بندی می‌کنم.

برای نمایش نتایج آماده، نصب مجدد یا تولید مجدد نمودارها لازم نیست. اگر بخواهم تولید جدول‌ها از پیش‌بینی‌های ثبت‌شده را زنده نشان بدهم:

```bash
python scripts/summarize_pilot.py
```

این فرمان از CSV و پیش‌بینی ذخیره‌شده نمودار می‌سازد، نه از امتیازدهی مجدد صوت. مسیر Python محیط را مانند مثال‌های بالا به کار می‌برم.

## ۷. اگر اینترنت کلاس قطع بود یا نصب مشکل داشت

کل پروژه را بعد از clone و نصب آماده نگه می‌دارم. برای اجرای زنده، مدل و وابستگی‌ها باید روی همان سیستم حاضر باشند. اگر فقط فایل‌های HTML، PNG، PDF و CSV آماده را کپی کرده باشم، می‌توانم خروجی ذخیره‌شده را بدون Python نشان بدهم، ولی صریح می‌گویم نمایش نتیجهٔ قبلی است و اجرای زنده نیست.

برای پشتیبان ارائه، دو گزارش HTML ساخته‌شده و پوشهٔ `results/pilot-summary/` را روی فلش نگه می‌دارم. نسخهٔ HTML تک‌فایلی تصویر و صوت پردازش‌شده را در خودش دارد.

## ۸. خطاهای معمول

- `Audio not found`: داخل پوشهٔ اصلی پروژه نیستم یا مسیر WAV/FLAC غلط است. برای مسیر دارای فاصله از کوتیشن استفاده می‌کنم.
- `No module named torch`: فرمان را با Python دیگری اجرا کرده‌ام؛ از `.venv` همین پروژه استفاده می‌کنم.
- خطای بارگذاری torchaudio: جفت نسخهٔ هماهنگ PyTorch/TorchAudio را طبق فرمان‌های بالا در محیط تازه نصب می‌کنم.
- `pretrained/full_seed0.pt` پیدا نمی‌شود: پروژه را کامل دریافت نکرده‌ام؛ وجود مدل را پیش از کلاس بررسی می‌کنم.
- صوت به قالب M4A یا قالب پشتیبانی‌نشده است: نسخهٔ WAV یا FLAC آماده می‌کنم؛ تغییر پسوند به‌تنهایی تبدیل فرمت نیست.
- خروجی اشتباه است: خطای نرم‌افزار را با خطای مدل اشتباه نمی‌گیرم. pilot روی دادهٔ بیرونی عملکرد ضعیفی داشته و این محدودیت بخشی از نتیجهٔ پروژه است.

من برای ارائه نیازی به اجرای آموزش یا دوباره‌سازی datasetهای اصلی ندارم و یک دمو را «اثبات دقت کلی» معرفی نمی‌کنم.
